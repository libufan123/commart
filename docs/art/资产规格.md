- **可访问性基线 = Standard**（MVP 出货目标）：16pt 正文下限、48/44pt 热区、语义色双编码+标签、浅/深双 Theme、Reduce Motion、动态字号。

## 2. 与 Godot 交付规格对齐

> 对齐 `可访问性分级与特性矩阵.md` §3；以下为美术侧给工程的准绳（不写代码）。

### 2.1 图集 / 纹理
- 图标、UI 小元素合并 **AtlasTexture** 合批，减 draw call；单图集 ≤ **2048×2048**。
- 压缩：**ETC2（Android）/ ASTC（iOS，建议 6×6 或 8×8 block）**；透明 UI 用 RGBA。
- 位图统一出 **@3x 高分**，引擎按需缩小（移动 GPU 缩小优于放大）。

### 2.2 字体
- **动态字体**（FontFile）加载，不烧字进图；中文子集化/预载常用字。
- 正文 16pt 下限在 `theme_default_font_size` 层强制；响应系统动态字号（Standard 至 ~200%）。

### 2.3 响应式 / 九宫格
- 卡片、按钮、Sheet 全部 **NinePatchRect**，圆角/边不随尺寸变形。
- 布局用 **Container + `get_safe_area()`** 锚定，适配 360dp 小屏 → 平板竖屏，单列。

### 2.4 纹理预算表（Standard 基线，供程基岩按机型调）
| 资产类型 | 单资产上限 | 切片首批估算 |
|---|---|---|
| 符号/图标（矢量，缓存位图 64–128） | 128×128 @3x | ~20 个，合批 |
| NPC 头像（256²，4 persona×3 态） | 256×256 | 12 帧 ≈ 单图集内 |
| 卡片 9Patch | 480×480 @3x | 3 张 |
| UI 组件 9Patch | 480×480 @3x | 5 张 |
| 引导角色（若采用） | 512×512 | 3 帧（待定） |
| 单图集 | ≤2048² | 美术侧合计 ≤ 2 图集 |
| **美术侧包体（切片）** | — | **建议 ≤ 8–12 MB**（与程基岩核对总包） |

## 5. 给 engineering-lead 的资产交付约束（请转交程基岩）

1. **真实文本不烧字**：所有可读文字（场景叙事、选项、复盘、标签）一律动态字体，任何「带字图片」评审一票否决。
2. **颜色走 Theme 变量**：浅/深切换仅换 Theme，美术不产双份位图；语义色（peri/honey/sage/amber）由 Theme 提供，工程拼接 UI 必须保留符号+文字双标签。
3. **九宫格 + 安全区**：卡片/按钮/Sheet 用 NinePatchRect，布局 Container 锚定 + `get_safe_area()`，适配 360dp。
4. **热区**：可点元素美术按 48pt 设计、44pt 硬下限；整张抉择卡可点。
5. **动效外置配置**：符号/卡片转场参数（220–320ms / ease-out / 位移≤12px / 克制 scale）写可调配置；系统 Reduce Motion 开启即退化为淡入/瞬切、停循环动画。
6. **图集与压缩**：图标 UI 合 AtlasTexture（≤2048²），ETC2/ASTC；位图统一 @3x 高分。
7. **纹理预算**：切片美术侧 ≤ ~8–12 MB、≤ 2 图集；最终以程基岩目标机型/总包为准，美术配合压缩降频。
8. **NPC 帧管理**：微表情为静态帧（非骨架动画），按 persona+mood 命名加载，避免运行时生成。
