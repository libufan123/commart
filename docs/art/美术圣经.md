> 项目：《沟通的艺术》情景抉择类沟通技能学习游戏
> 引擎：Godot ｜ 平台：iOS / Android（移动端竖屏优先）

## 0. 适用范围与一句话定位

本文档定义游戏的**视觉身份**（Visual Identity），覆盖：情绪定位、色彩、字体排版、图标符号、角色、场景/抉择卡、UI 组件、动效、竖屏与可访问性。

**一句话定位**：一个"陪你练习沟通"的温暖伙伴空间——不是考试、不是说教，而是一张让你坐下来、放心开口的桌子。

> ⓵ 待设计确认的锚点：游戏主循环命名暂用 **触发 → 技巧 → 后果**（Trigger → Technique → Consequence）三段式，源自技能文本中的"A2 触发场景 / E 可执行步骤 / 后果反馈"结构。若设计侧给出不同循环命名，本文第 4、6、7 节的符号与卡片需同步更名。

## 1. 视觉定位与情绪词

### 1.1 定位陈述
玩家是"想提升沟通/社交能力的人"，大多带着不安、怕说错、怕冲突而来。视觉的第一职责是**降低防御**——让练习显得安全、可逆、没有评判。

核心隐喻（建议，待设计确认）：**蜂巢与蜂蜜**。
- 原书第一章"要想采蜂蜜，就不要打翻蜂巢"是全书的情绪总纲。
- 「蜂蜜 = 好的关系/被看见的温暖」，是可采集、可练习的正向结果；「打翻蜂巢 = 批评/冲突」，是我们要帮玩家**绕开**的。
- 该隐喻天然温暖、有机、低攻击性，且能贯穿技能主题（倾听、赞赏、记住名字都是"采蜜"动作）。

备选/补充隐喻（若设计侧不采用蜂巢）：**"对坐的茶桌"**——两个圆润轮廓隔着一张小桌，象征平等、非审讯式的对话。

### 1.2 情绪词表（设计评审用）
| 我们要的（Target） | 我们要避开的（Anti） |
|---|---|
| 温暖 warm ｜ 安全 safe ｜ 松弛 relaxed | 高压 pressured ｜ 冰冷 cold ｜ 说教 preachy |
| 共情 empathic ｜ 坦诚 honest ｜ 鼓励 encouraging | 评判 judgmental ｜ 竞技 competitive ｜ 焦虑 anxious |
| 柔软 soft ｜ 有机 organic ｜ 呼吸感 breathable | 锐利 sharp ｜ 工业 industrial ｜ 拥挤 cluttered |

### 1.3 视觉基调三原则
1. **非评判**：后果卡不出现"红叉/扣分/失败"式羞辱视觉；用"关系温度"变化代替对错二分。
2. **可练习**：每个抉择都暗示"可以再试一次"，不锁死。
3. **低刺激**：无闪烁、无强对比跳变、无催促感计时器（除非玩家自选挑战模式）。

## 2. 色彩系统

### 2.1 设计约束
- 移动端可读性优先；所有正文文字对比度 ≥ 4.5:1，大字号 ≥ 3:1，UI 组件边界 ≥ 3:1。
- 语义色**不单独承载含义**，必须配合图标/文字标签（色盲友好，见第 9 节）。
- 提供浅色 / 深色两套，深色模式降低亮度、降低饱和、保留暖调（避免纯灰冷感）。

### 2.3 深色模式（Dark）
| 角色 | HEX | 说明 |
|---|---|---|
| 背景 | `#1C1A17` | 深暖炭，非纯黑 |
| 表面 | `#262320` | 卡片 |
| 表面次 | `#322E29` | 分区 |
| 主文字 | `#EDE7DF` | 暖白 |
| 次文字 | `#B3A99E` | |
| 主色 | `#D98C6A` | 提亮以保证对比 |
| 蜂蜜金 | `#E6B45A` | 略提亮 |
| 鼠尾草绿 | `#82B096` | 略提亮 |

深色模式要点：所有填充色降低饱和 ~10–15%，避免 OLED 上的刺眼感；语义色在深色下仍须对照第 9 节对比要求复核。

> ⓶ 待设计确认：深色模式是否默认跟随系统、或提供手动开关 + 首选项记忆。建议**两者都给**，默认跟随系统。

### 2.4 色板使用红线
- 蜂蜜金 `#E0A53E` **绝不作为小字号正文**（在米底对比仅 ~2.6:1）。
- 纯红 `#FF0000` 系列**禁止**用于任何后果/错误（与"低压力、非评判"冲突）。
- 单屏主色填充面积建议 < 30%，其余留给呼吸感的暖米底。

## 3. 字体与排版层级

### 3.1 字体选择（移动端）
- **中文正文**：系统人文无衬线栈（PingFang SC / Noto Sans SC）；若需统一跨平台外观，可打包圆体倾向的人文无衬线（如思源黑体 / 系统圆体）。
- **西文/数字**：与中文同栈的 Latin 部分（SF Pro / Noto Sans），数字优先等宽感以便"关系温度"读数。
- **风格倾向**：偏圆角、偏人性（humanist），**避免**硬朗几何无衬线（显冷、显制度）。
- 字体资源以 Godot `FontFile` / 动态字体加载，禁止把文字烧进图片（可访问性 + 多语言）。

### 3.2 字号阶梯（竖屏，单位 sp / pt，1pt≈1sp@基线密度）
| 层级 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| Display 标题 | 24–28 | Semibold | 1.3 | 章节/大场景标题 |
| H1 | 20–22 | Semibold | 1.35 | 卡片主标题 |
| H2 | 17–18 | Medium | 1.4 | 区块标题 |
| Body 正文 | **16（最小）** | Regular | **1.55–1.6** | 全部叙事/选项正文 |
| Caption 辅助 | **13（最小）** | Regular | 1.4 | 标签、脚注、元信息 |
| Tag 标签 | 12–13 | Medium | 1.2 | 触发/技巧/后果角标（配图标） |

**红线**：正文绝不低于 16sp，辅助绝不低于 13sp；中文行高≥1.5 防拥挤。

### 3.3 强调方式
- 优先用**字重 + 颜色 + 留白**做层级，不靠单一放大。
- 重点句：Ink + Semibold；不要用全大写（中文无大小写，西文慎用全大写，损可读）。
- 段落间距 > 行内间距，制造"呼吸感"。

## 4. 图标 / 符号语言

### 4.1 三类核心交互的统一符号（必读）
游戏主循环三段，各给一个**贯穿全游戏的固定符号**，配语义色，使玩家一眼识别"我现在在哪一步"。

| 类别 | 符号（建议） | 形态描述 | 语义色 | 含义 |
|---|---|---|---|---|
| **触发 Trigger** | ◌ 涟漪 / 对话气泡+？ | 同心涟漪圈，或带问号的圆角气泡 | 柔雾蓝 `#7E8AAE` | "有个情境出现了，需要你回应" |
| **技巧 Technique** | ⬡ 蜂巢格（带微光） | 六边形蜂巢单元 + 中心小光点 | 蜂蜜金 `#E0A53E` | "选择一个沟通技巧来应对" |
| **后果 Consequence** | ⑂ 分岔嫩芽 | 一条路径分两叉，末端冒出小嫩芽 | 绿(顺畅)/琥珀(紧张) | "看到这次选择带来的关系变化" |

> 符号在触发卡右上角、技巧卡左侧、后果卡顶部固定出现；配合文字标签（"情境 / 技巧 / 结果"），**不止靠颜色**。

### 4.2 图标通用规范
- 线宽 2px（@24 网格），圆头圆角，单色填充（取语义色或 Ink）。
- 网格 24×24 设计，导出 1x/2x/3x；Godot 用 `texture filter = linear`，避免锯齿。
- 风格：友好、非负重、无写实阴影；与"有机/温暖"基调一致。

### 4.3 章节 / 技能类别标记（6 篇，可选）
原书 6 篇可各配一个温和的章节符号（如：蜂巢/微笑/倾听/握手-叶/家/信），用于地图/进度。建议轻量，不抢主循环三符号的识别度。

### 4.4 关系温度计图标
- 用一段"藤蔓生长"意象表示关系温度：从光秃小枝 → 抽芽 → 开花，对应 紧张→平稳→亲近。
- **禁止**用红绿对撞的"心情脸"做唯一指示（色盲 + 评判感）。

## 5. 引导角色 / NPC 视觉

### 5.1 是否采用拟人化教练/陪练？——**建议：采用一个"伙伴"角色**
理由：纯文字分支游戏易显冷；一个低姿态、非说教的伙伴能承接"鼓励练习而非评判"的定位，并承担引导、复盘旁白。

### 5.2 伙伴（Guide）方向建议（三选一，待设计拍板）
| 方案 | 描述 | 利弊 |
|---|---|---|
| **A. 蜜蜂伙伴（推荐）** | 圆润、性别中立的小蜜蜂/蜂精灵，呼应蜂巢蜂蜜隐喻；非写实、低威胁 | 主题强绑定；需避免"被蜇"的负面联想（用圆身大眼软处理） |
| B. 抽象暖团 | 一团有表情的暖色软形体，无物种、无性别 | 最不让人投射/ intimidate；但记忆点弱 |
| C. 人类教练头像 | 真人风格教练 | 易显"老师/说教"，与"同伴"定位冲突，**不优先** |

> ⓷ 待设计确认：伙伴采用方案 A / B / C，及其命名与基础性格（建议：好奇、不评判、会先承认"这挺难的"）。

### 5.3 NPC（情景中的对话对象）视觉
- 用**简洁扁平头像**（圆形裁切 + 平涂肤色 + 极简表情），代表同事/伴侣/父母/陌生人是不同 persona。
- **多样性 + 中立**：肤色、年龄、发型的暖色平涂组合；**禁止夸张 caricature / 刻板印象**（原书案例含时代性别预设，视觉上须刻意去刻板）。
- 表情仅传达"平静/犹豫/开心/低落"等基础情绪，不做嘲讽式丑化。
- NPC 不作为"对手"，而是"你正在练习沟通的对象"。

## 6. 场景 / 抉择卡片视觉规范

> 情景抉择是核心界面。所有卡为**单列竖屏**，大点按区，软阴影，圆角 16–20px。

### 6.1 触发卡（情境卡）
- 结构：左上 NPC 小头像 + 关系标签（如"同事·周一晨会"）→ 右上 **触发符号 ◌** + "情境"角标 → 标题（H1）→ 2–4 句叙事正文（16sp）→ 底部"你面临一个选择"提示。
- 底色 Surface，左缘一道 4px 柔雾蓝细条标识"触发"。
- 不评判、不预设立场（叙述用第三人称/第二人称中性语气）。

### 6.2 技巧卡（选项卡）
- 每个抉择是一张可点卡，2–4 张纵向排列。
- 卡左侧固定 **技巧符号 ⬡**；卡内：选项标题（H2）+ 一句你会"说/做"的预览（16sp）。
- **不预先标注对错/推荐**：鼓励探索；复盘时才揭示用了哪条技巧、对应原书哪条技能。
- 可选"凭直觉回应"作为一张中性卡，接纳玩家真实反应。
- 选中态：Primary-tint 底 + 陶土细边 + 轻微 scale(1.02)。

### 6.3 后果卡（结果卡）
- 顶部 **后果符号 ⑂** + "结果"角标；用绿/琥珀区分顺畅与紧张（**配文字"关系升温 / 出现摩擦"**，不靠色）。
- 正文：一段关系走向叙述 + **关系温度计**可视化（藤蔓生长状态）。
- 语气非惩罚：即使"紧张"也写成"他沉默了，你们都需要一点时间"而非"你搞砸了"。
- 底部双按钮：**"再试一次 ↺"**（同一情境换技巧）/ **"看看沟通洞察"**（进入复盘）。

### 6.4 卡片通用几何
- 圆角 18px；阴影 `0 2px 8px rgba(46,42,38,.08)`（浅色）/ 更弱（深色）。
- 内边距 16–20px；最大文本行宽 ≤ 36 中文字（竖屏约一屏宽，天然满足）。
- 卡间距 12–16px，制造呼吸感。

## 7. UI 组件视觉

| 组件 | 规范 |
|---|---|
| **主按钮 Primary** | 填充陶土 `#B86A4D`，白字 Semibold 16sp，圆角 14px，**最小高 48dp**，底部拇指区优先放置 |
| **次按钮 Secondary** | 透明底 + 1px 陶土边 + 陶土字；同尺寸 |
| **幽灵按钮 Ghost** | 仅文字（Ink-2），无框，用于低优先级（如"跳过"） |
| **进度 Progress** | 章节进度用"蜂巢小格连成的路径"；技能掌握用已点亮的小六边形徽章，未点亮为浅陶描边 |
| **反馈 Feedback** | 正向：蜂蜜小光点 + 对勾（非大红勾）；负向：**不**用叉，用"↺ 再试一次"引导 |
| **复盘面板 Review** | 半屏 Bottom Sheet：本次用了哪条技巧（⬡+技能名）→ 关系温度变化（藤蔓）→ 一句"沟通洞察"（原书要点摘录，鼓励式语气）→ 可收藏 |
| **输入/选择态** | 选中 = Primary-tint 底 + 陶土边；未选 = Surface + 浅边 |
| **弹层/Toast** | 圆角 14px，米底或 Surface，2 行内，1.5s 自动消；不用红色报错条 |

**组件红线**：任何"失败/错误"视觉都走"柔和提示 + 可重试"，严禁羞辱式 UI。

## 8. 动效原则

### 8.1 总原则
轻量、移动端性能友好（Godot 下目标 60fps，中低端机不掉帧）。动效**只为意义服务**，不炫技。

### 8.2 参数基线
- 时长：卡片转场 220–320ms；点按反馈 120–160ms；微光循环 1.2–2s。
- 缓动：`ease-out` / 轻微 `spring` 回弹（overshoot ≤ 1.05，避免"弹跳过度"破坏安全感）。
- 位移：以"淡入 + 上移 8–12px"为主，避免大幅度滑屏。

### 8.3 允许 / 禁止
| 允许 | 禁止 |
|---|---|
| 卡片淡入上移、选中轻微放大 | 屏幕抖动 / 闪烁（触发焦虑） |
| 伙伴轻柔呼吸/微光（待机） | 长时间循环动画抢占注意力 |
| 成功时极少蜂蜜光点（≤8 粒） | 粒子风暴、景深模糊等大开销 |
| Tap 时有克制 scale + 可选轻 haptic | 强对比色彩瞬切 |

### 8.4 可访问性联动
- 必须尊重系统 **Reduce Motion**：开启时所有转场退化为纯淡入/瞬切，循环动画停用。
- 所有动效不得携带**唯一信息**（如"闪一下=成功"），须有静态文字/图标兜底。

## 9. 竖屏适配与可访问性基础

### 9.1 竖屏适配（Portrait-first）
- 单列布局；所有主操作落在**屏幕下半部拇指热区**。
- 处理刘海/圆角安全区（Safe Area Insets）：顶部与底部各留 ≥ 16dp 安全边距，Godot 用 `get_safe_area`。
- 最小可用宽度按 360dp（小屏安卓）设计，向上流式适配至平板竖屏。
- 文字与控件不依赖横滑；长文可纵向滚动。

### 9.2 对比度（WCAG AA 基线）
- 正文文字 ≥ **4.5:1**；大字号(≥18.66sp 粗 / 24sp 常规) ≥ **3:1**；UI 组件/边界 ≥ **3:1**。
- 提供**高对比模式**开关（可选 Comprehensive 特性）：强化 Ink 与底、加粗边界。

### 9.3 最小字号
- 正文 16sp、辅助 13sp 为硬下限（见第 3 节）；接入系统**字体缩放（Dynamic Type）**，支持最大 ~200% 不破版。

### 9.4 色盲友好（Color-blind safe）
- **语义不靠色 alone**：触发/技巧/后果三符号各有独立图形 + 文字标签；关系温度用藤蔓形态而非红绿条。
- 上线前用 **Deuteranopia / Protanopia / Tritanopia** 模拟器过一遍主流程截图。
- 避免"红=好/绿=坏"这类成对编码；好/紧张改用 绿/琥珀 + 图形。

### 9.5 触控热区
- 所有可点元素 ≥ **48×48dp**（Material）/ 对齐 Apple HIG **44×44pt**；选项卡整卡可点。
- 相邻可点元素间距 ≥ 8dp，防误触。

### 9.6 可访问性目标分级（建议）
- **基线出货 = Standard**：对比度 AA、最小字号、48dp 热区、Reduce Motion、色盲符号兜底。
- **Recommended = Comprehensive**（建议立项即纳入）：系统字体缩放、高对比模式、屏幕阅读器可达（文本结构化、无烧字图片）、字幕/旁白文本可读。
- Exemplary（后续）：自定义文字间距/行宽、单手模式、动态简化（减少动效/色彩的认知负荷模式）。
