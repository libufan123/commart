## 0. 总览与定位

本文档为美术侧对**可访问性（Accessibility）**的规范交付，给 engineering-lead 在 Godot 主架构里引用。它定义三档分级、特性矩阵，以及美术资产的 Godot 交付规格。

**核心立场（与设计基线一致）**：可访问性不是锦上添花，而是本游戏「低压力、高共情、鼓励练习」定位的基础要求——若一名色觉障碍或需要放大字体的玩家无法顺畅「练习沟通」，游戏价值即落空。

**分级口径**：采用 **Basic / Standard / Comprehensive** 三档（注：原美术圣经 §9 曾用 Exemplary 作远期档；此处收敛为三档以对齐 Phase 3 工程落地，Exemplary 作为后续可选扩展不在本交付强制范围）。

- **Basic**：能玩、能读、能点（底线，避免硬障碍）。
- **Standard**：舒适可用、主流无障碍场景覆盖（**MVP 出货目标**）。
- **Comprehensive**：深度适配、覆盖更广人群与极端设置（扩展层）。

## 1. 三档分级定义

> 所有阈值对齐 WCAG 2.1 AA 基线；pt 与 dp 按 1:1 计（iOS pt / Android dp 同义，下统称「pt」）。

### 1.1 Basic（底线）
| 维度 | 要求 |
|---|---|
| 对比度 | 正文 ≥ 4.5:1；大字号(≥18.66pt 粗 / 24pt 常规) 与 UI 边界 ≥ 3:1 |
| 最小字号 | 正文 16pt、辅助 13pt 硬下限（美术圣经 §3） |
| 色盲友好 | 关键语义（触发/技巧/后果）**至少**有图形符号，不单靠颜色区分 |
| 触控热区 | 可点元素 ≥ 44×44pt，相邻间距 ≥ 8pt |
| 动态字号 | 支持系统基础字号；不做缩放则至少不破版到不可读 |
| 深色模式 | 不强制；若仅浅色，需保证浅色下对比度达标 |
| 减少动效 | 不强制；动效本身不得承载唯一信息 |
| 屏幕阅读器 | 不强制；但文本须为真实文本（不得烧进图片）以利后续接入 |

### 1.2 Standard（MVP 出货目标）
在 Basic 之上增加：
| 维度 | 要求 |
|---|---|
| 对比度 | 同上 AA；**额外提供高对比开关**（强化 Ink 与底、加粗边界） |
| 最小字号 | 同上；并接入系统**动态字号（Dynamic Type）**，支持至 ~150% 不破版 |
| 色盲友好 | 语义**符号 + 文字标签双编码**；上线前过 Deuter/Protan/Tritan 模拟器 |
| 触控热区 | ≥ 48×48pt（Material）/ 对齐 Apple 44pt；整卡可点 |
| 动态字号 | 完整响应系统字号，最大 ~200% 主流程可用 |
| 深色模式 | **提供浅/深两套**，默认跟随系统 + 手动开关 + 记忆（美术圣经 §2.3） |
| 减少动效 | **尊重系统 Reduce Motion**：开启时转场退化为纯淡入/瞬切，循环动画停用 |
| 屏幕阅读器 | 文本结构化、控件有可访问名；无烧字图片；旁白/字幕文本可读 |

### 1.3 Comprehensive（扩展层）
在 Standard 之上增加：
| 维度 | 要求 |
|---|---|
| 对比度 | 提供 **AAA 档可选**（正文 ≥ 7:1），高对比模式可切换 |
| 最小字号 | 动态字号支持 ≥ 200% 且布局重排（非简单裁切） |
| 色盲友好 | 提供色盲滤镜/调色板切换（如 Deuteranopia 友好预设） |
| 触控热区 | 可选「单手模式」（主操作下沉至底部拇指区，美术圣经 §9.1） |
| 动态字号 | 用户自定义字间距/行宽（缓解阅读障碍） |
| 深色模式 | 深色资源独立优化（降饱和、提亮语义色，美术圣经 §2.3 表） |
| 减少动效 | 提供游戏内「简化视觉」档：减少粒子/光效/色彩跳动 |
| 屏幕阅读器 | 完整 VoiceOver/TalkBack 走查；语音旁白可选配音 |

## 2. 特性矩阵（视觉系统 × 三档）

> 映射美术圣经各系统。标记：● 达标项 ／ ◐ 部分/可扩展 ／ — 不在该档。

| 视觉系统（美术圣经章节） | Basic | Standard（MVP） | Comprehensive |
|---|---|---|---|
| **色彩系统**（§2） | ● AA 对比度底线；● 禁纯红/禁蜂蜜金作小字 | ● 浅/深双套；● 高对比开关；◐ 色盲预设 | ● AAA 可选；● 色盲调色板切换 |
| **字体与排版**（§3） | ● 正文16/辅助13 下限；● 真实文本 | ● 动态字号至150%；● 200%不破版 | ● ≥200%重排；● 自定义字间距/行宽 |
| **图标/符号语言**（§4） | ● 触发◌/技巧⬡/后果⑂ 各有独立图形 | ● 符号+文字双编码；● 色盲模拟过测 | ● 色盲友好预设包 |
| **引导角色/NPC**（§5） | ● 角色非评判、非丑化 | ● NPC 多样性去刻板；● 表情基础情绪清晰 | ● 可选角色/旁白配音 |
| **场景/抉择卡片**（§6） | ● 单列竖屏；● 卡≥44pt热区 | ● 整卡可点48pt；● 后果藤蔓非色盲依赖 | ● 简化视觉档降动效 |
| **UI 组件**（§7） | ● 主操作拇指区；● 无红叉惩罚UI | ● 反馈↺再试；● 复盘Bottom Sheet可读 | ● 单手模式；● 组件高对比变体 |
| **动效原则**（§8） | ● 动效不承载唯一信息 | ● Reduce Motion 联动 | ● 游戏内简化视觉档 |
| **竖屏适配/可访问性**（§9） | ● 安全区insets；● 360dp小屏 | ● 动态字号；● 色盲兜底；● 高对比 | ● 单手模式；● 自定义排版 |

**MVP 结论**：以 **Standard** 为出货基线（与美术圣经 §9 原「Standard 基线 + Comprehensive 推荐」一致）；Basic 作为兜底兼容（任何机型/设置下不至于不可玩）；Comprehensive 作为发布后扩展，不阻塞首版。

## 3. Godot 美术交付规格建议（给工程引用）

> 本节约为**约束与建议**，由 engineering-lead 在架构落实；art-director 不写代码、不下工程定论。

### 3.1 资源格式
- **图标/符号（◌⬡⑂、章节标记、关系温度计藤蔓）**：优先 **矢量 SVG**，导入 Godot 用 `SVGTexture` 或在编辑器转 `Texture2D`；保证任意缩放（尤其动态字号放大、Retina/xxhdpi）不糊。
- **位图类（角色立绘、NPC 头像、背景氛围）**：导出 **PNG-24 + 透明通道**，按 1x/2x/3x（@1x=基准密度 mdpi/xxhdpi 对应）三档，或统一出 **3x 高分**由引擎按需缩小（移动端 GPU 缩小比放大质量好）。
- **禁止**：任何承载可读文字的美术资产（文字必须真实文本，见 §1/§9）。

### 3.2 图集 / 纹理（Atlas）
- 图标、UI 小元素合并为 **TextureAtlas（AtlasTexture）**，减少 draw call。
- 单图集建议 ≤ 2048×2048（兼容中低端 OpenGL ES 3.0 / Vulkan 移动 GPU）；超大背景可单独走流式加载。
- 纹理压缩：**ETC2（Android）/ ASTC（iOS 与通用推荐）**；透明 UI 用 RGBA。

### 3.3 字体加载
- 用 Godot **动态字体（FontFile / 动态字体加载）**，不烧字进图。
- 中文打 **子集化/按需缓存** 或预载常用字（情景抉择文案量可控）；西文/数字同栈。
- 字号以 `theme_default_font_size` + 乘法系数响应系统动态字号，**正文 16pt 下限在 theme 层强制**。

### 3.4 九宫格 / 响应式卡片
- 卡片背景用 **NinePatchRect（StyleBoxTexture 九宫格）**，保证不同文案长度下圆角/边不变形——呼应美术圣经 §6「单列竖屏、呼吸感」。
- 抉择卡布局用 **Container 锚定 + 安全区 margin**（Godot `get_safe_area()`），而非写死像素，适配 360dp 小屏到平板竖屏。

### 3.5 移动端纹理尺寸预算（建议基线，供程基岩按目标机型调）
| 资产类型 | 单资产建议上限 | 备注 |
|---|---|---|
| UI 图标（单） | 64×64 ~ 128×128 @3x | 矢量优先，位图仅缓存 |
| NPC 头像 | 256×256 | 圆形裁切，平涂 |
| 伙伴立绘 | 512×512 | 圆润蜜蜂/暖团，低面 |
| 背景氛围 | 1080×1920（竖屏全屏） | 可压缩、可降频 |
| 单图集 | 2048×2048 | 防超 GPU 限制 |
| 安装包纹理总量 | ≤ 约 30–50 MB（美术侧） | 与程基岩核对整体包体 |

### 3.6 深色模式资源策略
- **颜色走 Godot Theme 变量**（如 `bg / surface / primary`），浅/深两套 Theme 切换，**不**为每帧出两套位图（除必要美术氛围图）。
- 语义色与符号在深色下调用同 §2.3 表的提亮值；切换时只换 Theme，不动布局。
- 氛围背景如需双版，建议用**同一图 + 深色叠加层/调色**，减少包体。

### 3.7 与 Reduce Motion / 动态字号 的工程接口（约定）
- 美术交付的动效参数（时长/缓动/位移，见美术圣经 §8.2）写入可调配置；工程读取系统 `OS` 无障碍标志后统一降级。
- 文字容器绑定动态字号系数，美术不写死换行像素。

## 4. 落地点检（供 QA / 工程）
- [ ] 主流程在 Deuter/Protan/Tritan 模拟下可读（符号+文字双编码生效）
- [ ] 系统字号拉到 200% 主流程不破版
- [ ] 开启 Reduce Motion 后无循环动画、无纯动效承载信息
- [ ] 浅/深切换仅换 Theme、布局不变
- [ ] 最小热区 48pt 实测（用真机/布局边界视图）
- [ ] 对比度 AA 用工具实测（陶土白字、蜂蜜金不作正文两条红线）

## 5. 待确认 / 与设计·工程对齐项
- **分级命名**：本文用 Basic/Standard/Comprehensive 三档，与美术圣经 §9 早期「Standard+Comprehensive+Exemplary」口径略有收敛，建议设计侧在 GDD 统一采用三档口径。
- **MVP 档**：建议锁定 **Standard** 为出货基线；若工期压力，Basic 兜底但须明确告知「部分无障碍未覆盖」。
- **屏幕阅读器深度**：Comprehensive 档要求语音旁白，涉及文案/音频跨职能，需文策渊（UX 规格引用本分级）+ 阮和鸣（音频）协同，不在美术侧单方可定。
- **纹理预算**：§3.5 为建议值，最终以程基岩目标机型/包体为准。
