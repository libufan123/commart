## 1. 目标与范围

### 1.1 本规格服务什么
本 UX 规格把垂直切片（**s01 不批评 + s03 显要感 + s04 真诚赞赏，共 5 场景：s01×2 + s03×2 + s04×1**）的交互落为可直接实现的规格。它对接：
- 垂直切片 GDD §6 的**六屏**（主菜单/技能地图、场景卡、识别面板、选项卡、后果演出、复盘面板）；
- 架构 `engin-architecture.md` §3 的**场景/节点划分**（S2→S3→S4→S5→S6 状态机 + S7/S8 导航），以及 §5 竖屏适配层、§6 状态与存档。

### 1.2 设计支柱约束（P1 / P3 / P4，P2 已移除）
- **P1 后果可见不说教**：后果由 NPC 反应与关系符号说话；复盘用「X 身上发生过」案例，无「你必须」口吻、无红叉/扣分羞辱视觉。
- **P3 识别优先于技巧**：S3 识别是 S4 的**硬闸门**，未识别不可进入有效抉择。
- **P4 低门槛高频可重玩**：单屏单局 ≤ 3 分钟，〔再练一次〕零冷却，无分数压力。
- 设计理论红线自检：**无主导策略**（选项卡不标对错、不暗示「正确」路径）、**无经济失衡**（本切片无经济系统）、**无认知过载**（一次一屏、元素克制）、**无支柱漂移**（六屏均服务上述三支柱）。

### 1.3 本规格**不**涵盖（明确边界）
- ❌ 完整 34 技能 / 6 篇全量导航——本规格仅切片内 s01/s03/s04。
- ❌ **S9 关系账户 meter**——推迟扩展层；`relationshipSignal` 仅本局展示、不持久化（架构约束3 / ADR-005）。
- ❌ **扩展层伙伴角色立绘（美术圣经 ⓷ 待拍板）**——MVP 用「三符号 + 文字旁白」承载引导/复盘，不产伙伴立绘（资产规格 §1.5）。
- ❌ s05 质量门（控制清单 G6，前瞻，不进 MVP）。
- ❌ 任何 Godot 场景文件 / 脚本代码——本规格为纯文档交付。

## 2. 竖屏单屏卡交互流（六屏 wireflow）

> 通用布局基线（所有六屏共用）：根 `MarginContainer` 施加**安全区内边距**（顶部/底部 ≥ 16dp，Godot `get_safe_area()`，架构 R3）→ 内部 `VBoxContainer` / `ScrollContainer`。**一次只渲染一屏**，由 `PlaySession` 状态机互斥切换（架构 §3、控制清单 C6）。正文 16pt 下限、热区 ≥ 48pt（对齐 Android 48dp / iOS 44pt，控制清单 C5）。无写死像素坐标（控制清单 C3）。

### 2.0 全局流转（六屏 + S3 闸门分支）

```

      │ 点技能 → 点场景
      ▼
场景卡 (S2) ──〔继续〕──▶ 识别面板 (S3)
                              │
                      单点提交标签
                              │
                 ┌────────────┴─────────────┐
          识别正确 (trigger_correct)   识别错误 (≠ correct)
                 │                          │
                 ▼                          ▼
           选项卡 (S4)              后果演出·miss (S5)
                 │                  (播放 triggers.miss，跳过 S4)

```

### 2.1 主菜单 / 技能地图（S8）

- **屏幕目的**：第 1 篇入口，呈现切片技能（s01 / s03 / s04）与掌握度小标记，进入单局。对应系统 S8（架构 `MainMenu.tscn` + `SkillMap.tscn`）。
- **UI 元素清单**
  - 标题区：游戏名 Display 标题 + 篇章标记 `sym_chapter_01` + 篇章名「第 1 篇 · 蜂巢与蜂蜜」（美术圣经 §4.3 / 资产规格 §1.1）。
  - 技能条目（SkillEntry）×3：每行 = 技能标题（H1）+ 掌握度 hex 小标记（S7，点亮/未点亮六边形 `ui_hex_on`/`ui_hex_off`）+ 场景数脚注。
  - 底部拇指区：〔设置〕（ico_settings）、〔继续上次〕（进入最近未完场景，可选）。
- **信息架构（来自数据）**：读 `skills_index.json`（架构 §6.4）渲染——`skills[].title`、`section`、`scenes[]`；掌握度来自 `SaveManager.save_v1.json` 的 `mastery{skillId:0–3}`。**场景 Schema 字段不在此屏直接消费**，仅借索引元数据。
  - ⚠️ 依赖缺口：`skills_index.json` 当前**尚未创建**（仓库未检索到）。需 Phase 4 由 data/eng 按架构 §6.4 结构落地，S8 硬依赖（控制清单 F1）。切片需含 `s01-shake-the-hive` / `s03-*` / `s04-genuine-praise-standard` 三条，各带 `scenes` 数组（s01×2 / s03×2 / s04×1）。
- **单屏布局要点**：单列滚动；篇章标记居顶；技能条目为整行可点卡片（≥48pt 高）；底部固定〔设置〕〔继续〕于拇指区。
- **状态 / 转场**：点技能条目 → 进入「技能详情态」（同屏内容切换，仍为单屏）：列出该技能 `scenes[]` 各场景按钮（标题取自场景 `title`）；点场景 → 启动 `PlaySession`，载入 `DataLoader.get_scenario(id)` 进 S2。已掌握（S7=3）条目 hex 全亮。
- **手势 / 点击热区**：技能条目整卡可点，最小高 48pt，条目间距 ≥ 8pt。

### 2.2 场景卡（S2）

- **屏幕目的**：呈现情境背景、对方最后一句、玩家本能「冲动」气泡，引导进入识别。对应系统 S2（架构 `ScenarioCard.tscn`）。
- **UI 元素清单**
  - 左上：NPC 微表情剪影（圆裁，按 `npc.mood` 选帧：`npc_<persona>_<mood>`）+ 关系标签（如「下属·绩效季」=`npc.role` 语境化）。
  - 右上：**触发符号 ◌** + 「情境」角标（`ui_tag_9p` 承载，periwinkle `#7E8AAE`，美术圣经 §4.1 / §6.1）。
  - 标题（H1）= 场景 `title`。
  - 叙事正文（Body 16pt）：`context` +（若 `npc.line` 存在）对方末句气泡 `NpcLineBubble`。
  - 底部**冲动气泡** `ImpulseBubble`：`impulse`（E4 信息层，不约束选择）。
  - 底部主操作：〔继续〕（Primary，进 S3）。
- **信息架构（来自 Schema）**：`title` / `context` / `npc{name,role,mood,line?}` / `impulse`。
- **单屏布局要点**：`card_trigger_9p` 底板（左缘 4px 柔雾蓝细条，美术圣经 §6.1）；叙事区可纵向滚（超长时 ScrollContainer）；冲动气泡落拇指区上方。
- **状态 / 转场**：〔继续〕→ 切 S3（淡入上移 ≤12px，架构 §5 / 美术圣经 §8.2）。读 `npc.mood` 决定剪影帧；`npc.line` 缺省则仅显 `context`+`impulse`（Schema 允许降级）。
- **手势 / 点击热区**：〔继续〕按钮 ≥48pt；NPC 剪影非热区（纯信息）。

### 2.3 识别面板（S3，P3 硬闸门）

- **屏幕目的**：呈现 2–4 候选标签，玩家单点提交；**识别正确才解锁 S4，识别错误直接演出 `triggers.miss`**（跳过 S4，见 §3）。对应系统 S3（架构 `TriggerPanel.tscn`）。
- **UI 元素清单**
  - 顶部：**触发符号 ◌** + 「识别情境」角标（提示「先看清情况再动手」）。
  - 标题微提示：「这个情境，最像哪一种？」（非指令式，呼应 P1 不说教）。
  - 候选标签按钮 `TagButton[]` ×2–4：每按钮 = 一行候选文本（`triggers.candidates[i]`），整卡可点，选中态 = Primary-tint 底 + 陶土细边（美术圣经 §7 输入/选择态）。
  - **无**「提交」独立按钮——单点即提交（保持竖屏单屏节奏，见 §3）。
- **信息架构（来自 Schema）**：`triggers.candidates[]`、`triggers.correct`（仅引擎内部校验，UI 不展示对错）、`triggers.miss`（识别错时由其 `npcReaction/relationshipSignal/judgement` 驱动 S5）。
- **单屏布局要点**：`VBox` 纵向排列 `TagButton`；按钮最小高 48pt、间距 ≥8pt；标签文本 16pt（Caption 角标 13pt）。
- **状态 / 转场（P3 闸门核心）**
  - 玩家单点某 `TagButton` → 引擎比对 `selected_trigger` 与 `triggers.correct`：
    - **正确**（`== correct`）：淡出 S3 → 进入 S4（解锁全部 `choices`）。
    - **错误**（`!= correct`）：**不提示对错**，淡出 S3 → 直接进入 S5 并播放 `triggers.miss`（后果自己说话，E1 错位自学）。若数据未配 `miss`，回退「选项集错位、后果由所选 choice 的 consequence 决定」（Schema G2 / 架构 §3）。
  - S3 未完成（未选标签）时，**S4 不可见/不可操作**（硬闸门，控制清单 D2/D3）。
- **手势 / 点击热区**：`TagButton` 整卡可点 ≥48pt。

```
┌──── 安全区 ────┐
│ (◌ 识别情境)    │
│ 这个情境最像哪一种？│
│ ┌────────────┐ │
│ │ 我正想批评/  │ │  TagButton(整卡可点)
│ │ 对方在防御   │ │
│ └────────────┘ │
│ ┌────────────┐ │
│ │ 对方需要被看见│ │  TagButton
│ └────────────┘ │
│ ┌────────────┐ │
│ │ 纯事务沟通   │ │  TagButton
│ └────────────┘ │
│ ┌────────────┐ │
│ │ 对方在撒谎   │ │  TagButton
│ └────────────┘ │
└──── 安全区 ────┘  单点即提交，无独立确认
```

### 2.4 选项卡（S4）

- **屏幕目的**：呈现 2–4 句真实回应（熟练/陷阱/边界），捕获玩家选择并透传类型。对应系统 S4（架构 `ChoicePanel.tscn`）。**仅当 S3 识别正确时到达**。
- **UI 元素清单**
  - 顶部：**技巧符号 ⬡** + 「技巧」角标（honey `#E0A53E`，美术圣经 §4.1 / §6.2）。
  - 选项卡 `ChoiceCard[]` ×2–4：每卡左侧 ⬡ + 卡内「你会说/做」预览（`choices[i].text`），整卡可点；**样式不标对错**（不显示 skilled/trap/boundary 标签，不暗示推荐，满足 P1 + 无主导策略）。
  - 可选一张中性卡「凭直觉回应」接纳真实反应（美术圣经 §6.2）。
  - 选中态：Primary-tint 底 + 陶土边 + 轻微 scale(1.02)（美术圣经 §6.2）。
- **信息架构（来自 Schema）**：`choices[].id` / `choices[].type`（仅引擎透传，UI 不渲染类型名）/ `choices[].text`。
- **单屏布局要点**：`VBox` 纵向 `ChoiceCard`；整卡可点 ≥48pt 高；卡间距 12–16pt（呼吸感）。超长时 ScrollContainer。
- **状态 / 转场**
  - 玩家单点 `ChoiceCard` → 提交 `chosen_choice_id` / `chosen_type` → 进入 S5，查表所选 `consequence`（ADR-004 静态映射）。
  - **E2 边界强制**：场景 `forceBoundary:true` 时，若所选 `type != boundary`，引擎确定性覆盖路由到 boundary 后果，并轻提示「此情境必须叫停，不在本技能范围」，不奖励软化（GDD §5 E2 / 控制清单 D6）。
- **手势 / 点击热区**：`ChoiceCard` 整卡可点 ≥48pt。

```
┌──── 安全区 ────┐
│ (⬡ 技巧)        │
│ 你会怎么回应？   │
│ ┌─⬡──────────┐ │
│ │ 把「让他认错」│ │  ChoiceCard(skilled,不标)
│ │ 换成下周三前…│ │
│ └────────────┘ │
│ ┌─⬡──────────┐ │
│ │ 把他三次延误 │ │  ChoiceCard(trap,不标)
│ │ 都列出来…   │ │
│ └────────────┘ │
│ ┌─⬡──────────┐ │
│ │ 涉及合规漏报│ │  ChoiceCard(boundary,不标)
│ │ 必须叫停   │ │
│ └────────────┘ │
└──── 安全区 ────┘  单点即提交
```

### 2.5 后果演出（S5）

- **屏幕目的**：静态查表演出对方反应 + 判词 + 关系信号符号；反馈由后果自己说话（P1）。对应系统 S5（架构 `ConsequenceStage.tscn`）。
- **UI 元素清单**
  - 顶部：**后果符号 ⑂** + 「结果」角标，按 `relationshipSignal` 取 `sym_consequence_smooth`（绿，≥0）/ `sym_consequence_tension`（琥珀，<0）+ **文字标签**「关系升温 / 关系平稳 / 出现摩擦」（双编码，标准色盲兜底）。
  - NPC 反应区：`npcReaction`（对方台词）+ NPC 剪影按 `relationshipSignal` 切换微表情（正→`warm`、负→`mood` 紧张态、0→`neutral`）。
  - **关系温度计（藤蔓三态）** `sym_vine_bare/_sprout/_bloom`：光秃(−1) / 抽芽(0) / 开花(+1)，**用形态而非红绿**承载温度（美术圣经 §4.4）。
  - 判词区：`judgement`（一句后果，非惩罚语气，如「他沉默了，你们都需要一点时间」）。
  - 底部双按钮：〔再试一次 ↺〕（ico_replay）/〔看看沟通洞察〕（进 S6）。
- **信息架构（来自 Schema）**：正常路径 = 所选 `choice.consequence{npcReaction, relationshipSignal, judgement}`；**识别错路径** = `triggers.miss{npcReaction, relationshipSignal, judgement}`（结构与 consequence 同构）。NPC 微表情帧取 `npc.role`+`mood`/温度态。
- **单屏布局要点**：`card_consequence_9p` 底板（顶部预留 ⑂ 区）；后果符号 + 藤蔓 + 文字三重冗余呈现关系变化（双重编码 + 形态）；无红叉/扣分。
- **状态 / 转场**：〔再试一次 ↺〕→ 回到 S2（同场景重练，E3 安全失败、零冷却）；〔看看沟通洞察〕→ S6。
- **手势 / 点击热区**：双按钮 ≥48pt，落拇指区。

```
┌──── 安全区 ────┐
│ (⑂ 结果) 〔出现摩擦〕│  amber + 文字(双编码)
│  ( vine: 光秃 )     │  藤蔓三态(形态承重)
│ [NPC紧张剪影]       │
│ npcReaction 台词…   │
│ ───────────────    │
│ judgement 判词…     │  非惩罚语气
│ 〔↺ 再试一次〕〔洞察〕│ ← 拇指区双按钮
└──── 安全区 ────┘
```

### 2.6 复盘面板（S6）

- **屏幕目的**：展开机制 + 真实案例 + 迁移线索，提供再练/下一导航；用「X 身上发生过」而非「你必须」（P1，P2 已移除）。对应系统 S6（架构 `ReviewPanel.tscn`，半屏 Bottom Sheet 或整屏均可，本切片用整屏单列以满足单屏可达）。
- **UI 元素清单**
  - 顶部：本次所用技巧揭示「⬡ + 技能名」（`skill` 字段映射，如「s01 不批评 / 打翻蜂巢」）+ 关系温度变化（藤蔓态）。
  - 机制段（H2「为什么」）：`review.mechanism`。
  - 案例段（H2「真实发生过」）：`review.case`（缺失则降级仅显机制+迁移，E5 / 控制清单 A7）。
  - 迁移段（H2「下次怎么做」）：`review.migration`。
  - 底部导航：〔再练一次 ↺〕/〔下一场景〕/〔返回地图〕（见 §4.3）。
- **信息架构（来自 Schema）**：`review{mechanism, case, migration}` + `skill`（揭示技巧名）+ 本次 `relationshipSignal` 藤蔓态。

## 3. 触发识别 UX（S3，P3 支柱承载）

### 3.1 候选标签呈现
- 候选标签以 `TagButton` 整卡呈现（美术圣经 §7 输入/选择态），**符号 ◌ 出现在面板右上角标**（「识别情境」），不在每个按钮上重复（避免视觉噪音）；按钮内仅文本 `triggers.candidates[i]`。
- 选中态 = Primary-tint 底 + 陶土细边 + 轻微 scale(1.02)；未选 = Surface + 浅边。
- **不显示「正确/错误」「推荐」任何字样或图标**——满足 P1 不说教 + 无主导策略红线。

### 3.2 识别错误的「可感知错位」反馈（E1，不直接提示对错）
核心机制：**识别错误不在 S3 给任何对错反馈**，而是让后果自己说话——引擎按 G2 方案A 直接演出 `triggers.miss`，玩家在 S5 后果卡上**可感知错位**：

1. **符号翻转**：后果卡顶部 ⑂ 由「顺畅（绿）」翻为「紧张（琥珀）」，配文字「出现摩擦」（双编码，不靠色）。
2. **藤蔓退化**：关系温度计由「开花」退为「光秃」，用形态承载温度下跌。
3. **NPC 剪影**：由中性态切到 `mood` 紧张态（如 defensive）。
4. **判词点明错位根因**（非评判玩家）：如 s01「你没先看清『他在防御』就进了抉择，局面已被拖进对抗；先诊断再动手」——把焦点放在「诊断顺序」而非「你错了」。

> 这种「可感知错位」让玩家**自行发现**「我没看清情况」，比显式打叉更符合 P1/P3 与「非评判」美术红线（美术圣经 §1.3）。`triggers.miss` 缺省时回退选项错位自然反噬，不崩溃（Schema G2 / 架构 §3）。

### 3.3 冲动气泡（E4）为信息层
- `impulse` 气泡仅在 S2 场景卡暴露玩家本能念头，**不约束、不否决**任何后续选择；玩家读完冲动仍可正常选熟练路径（GDD §5 E4 / 控制清单 D9）。气泡纯信息层，非闸门、非提示。

### 4.1 技能地图入口与章节点（S8）

### 4.2 掌握度 S7（轻量 0–3，无分数压力）
- 规则（GDD §4.2）：完成全部场景且至少一次选 skilled 且读过复盘 → 3（掌握）；完成但仅靠 trap → 2（体验过）；未完成 → 1（进行中）；未进入 → 0。

### 4.3 单局内导航语义
| 按钮 | 语义 | 目标 |
