## 1. 概述（Overview）

首个可玩切片，目标是在最小内容下验证「好玩且能学到」与核心循环（识别→抉择→后果→复盘）。

- **s01 不批评 / 打翻蜂巢**：一条「别做 X」的禁令场景，陷阱选项「把证据摆全让他认错」精准对应玩家真实本能，后果为负收益（反直觉、易戏剧化），最契合 P1。
- **s03 显要感 / 自重感**：一条「去做 Y」的供给场景，自带「诊断 vs 操作」双子循环，教可迁移心智模型，验证 P3。
- **s04 真诚赞赏**：测试「供给侧生成」交互（锁定最小真实单元 / 颗粒度倒置）；纳入切片作为第三个技能，与 s01 禁令、s03 供给形成「禁令—供给—生成」三轴对照。

切片不含关系账户 meter、不含 P2 伦理批注；反馈由后果 + 复盘承载。

## 2. 机制（Mechanics）

切片内单局流程：
1. 场景卡呈现（S2）：背景 + 对方最后一句 + 玩家「冲动」气泡。
2. 触发识别（S3）：s01 标签候选含「我正想批评/对方在防御」等；s03 含「关系恶化找原因」「对方需要被看见」等；s04 含「作品问题很多但需鼓励」「对方需要被看见」等。识别正确才解锁该技能选项；识别错误直接播放 `triggers.miss`（见 `内容数据schema.md` G2）。
3. 抉择（S4）：2–4 选项（熟练/陷阱/边界）。s01 熟练=改写目标指向未来行为；陷阱=列证据让他认错；边界=安全/合规必须叫停。s03 熟练=诊断削减落点 + 设计具名供给；陷阱=用钱/忽略需求；边界=对方高自恋/结构性问题。s04 熟练=锁定一个可被核对的具体点真诚夸 + 宽泛评；陷阱=泛泛夸「做得好」（油腻、不可核对）；边界=作品存在严重错误/合规问题时不得假夸。
4. 后果（S5）：静态查表演出对方反应 + 判词（展示用关系信号，不持久化）。
5. 复盘（S6）：机制 + 真实案例（A1）+ 迁移线索；「再练一次 / 下一场景」。

**场景清单（切片，共 5 个）**
- s01_scene_01「那封绩效评语」（陷阱+熟练+边界三选项）
- s01_scene_02「冷战僵局」（识别+陷阱变体）
- s03_scene_01「突然冷淡的同事」（诊断→操作）
- s03_scene_02「留不住的老员工」（供给具名化）
- s04_scene_01「问题很多的作品」（锁定最小真实单元 / 供给侧生成）

### 2.5 s04 场景片段（八节简版）

为验证「供给侧生成」交互，切片纳入 1 个 s04 场景。以下按八节简列，完整数据由 `内容数据schema.md` 驱动。

- **概述**：玩家面对一份问题很多、但作者仍需被鼓励的作品 / 方案；目标是练「精确夸、宽泛评」。
- **机制**：S3 识别「作品问题很多但需鼓励」→ S4 三选项（熟练=锁定一个可被核对的具体点真诚夸 + 宽泛评；陷阱=泛泛夸「做得好」；边界=存在严重错误/合规问题时不得假夸）→ S5 后果 → S6 复盘（案例：卡耐基「精确地夸、宽泛地评」）。
- **数据**：`skill: s04-genuine-praise-standard`；`npc.line` 取作者最后一句（如「我知道还有坑，但先给点反馈呗」）；`triggers.correct = "作品问题很多但需鼓励"`，并配置 `triggers.miss`（识别错→播放错位后果）。
- **公式**：无新增；复用 §4.1 识别准确率、§4.3 关系信号。
- **边缘**：E1（识别错→`miss`）、E2（边界：严重错误时强制 boundary，不得假夸）、E3（重复选陷阱安全失败）。
- **UI**：复用 §6 六屏；选项卡文案写成「真实会说的话」。
- **依赖**：S1(s04_scene_01) → S2 → S3 → S4 → S5 → S6，与其他切片场景同级。
- **验收**：s04_scene_01 可从场景卡跑通至复盘；熟练路径演示「锁定具体点」、陷阱路径演示「泛泛夸的油腻」、边界路径在严重错误时强制叫停。

## 3. 数据（Data）

全部内容由 `内容数据schema.md` 的 JSON/YAML 驱动，本切片不写死文案。关键字段：

## 4. 公式（Formulas）

切片仅保留轻量、可评审的计算，避免过早经济化。

**4.1 识别准确率（诊断质量，P3）**
```
识别准确率 = 识别正确场景数 / 进入场景数        （展示用，不评分压力）
```

**4.2 掌握度（S7，三档）**
```
掌握度(skill) =
  完成该技能全部场景 && 至少一次选 skilled 且读过复盘  → 3（掌握）
  完成全部场景但仅靠 trap 学会                      → 2（体验过）
  未完成全部场景                                    → 1（进行中）
  未进入                                            → 0
```

**4.3 关系信号（S5 展示用，不持久化）**
```
relationshipSignal ∈ { -1, 0, +1 }   // 仅本局演出，扩展层才累积为 S9 账户
```
> 单位：无（展示符号）。MVP 不跨场景累积。

## 5. 边缘情况（Edge Cases，≥3 类）

**E1 · 识别错误**：玩家选错标签 → 引擎**直接播放 `triggers.miss`**（G2 方案A，清晰、可感知的错位后果，如 s01 误判为「纯事务沟通」则触发 miss 反噬）→ 玩家自行发现「我没看清情况」。处理：不在识别步给对错提示，让 `miss` 后果教书；复盘点明「先诊断」。若某场景数据未配 `miss`，回退原逻辑（选项集错位，后果由所选选项 `consequence` 决定）。

**E2 · 边界情境误用**：s01 遇安全/合规漏报，玩家选「熟练路径（软化）」→ 系统强制切到 boundary 提示：「此情境必须叫停，不在本技能范围」→ 不奖励软化。处理：boundary 选项优先级高于 skilled，数据层标记 `forceBoundary: true`。

**E3 · 重复选陷阱**：玩家在同一场景连续两次选 trap → 后果照常反噬，复盘照常展开；不封锁、不扣分，保持「安全失败」。处理：重练无冷却，鼓励试错。

**E4 · 冲动气泡与熟练路径冲突**：玩家读「冲动」气泡后仍能选熟练路径 → 正常；气泡仅暴露本能，不约束选择。处理：气泡为信息层，非闸门。

**E5 · 空数据/缺失字段**：某场景 `review.case` 缺失 → 复盘仅显示机制+迁移，不崩溃。处理：Schema 校验在加载期报错，运行时降级。

## 6. UI 接口（UI Interface，关键屏幕）

竖屏单屏优先，3 分钟一局。

| 屏幕 | 内容 | 对应系统 |
|---|---|---|

## 8. 验收标准（Acceptance Criteria）

切片视为完成当且仅当：

1. **可玩闭环**：s01、s03、s04 各至少 1 个场景可从「场景卡→识别→抉择→后果→复盘→再练」完整跑通，无代码写死文案。
2. **P3 闸门有效**：未做触发识别无法进入有效抉择；识别错会触发可感知错位后果（优先播放 `triggers.miss`，无 `miss` 则选项错位）。
3. **陷阱真实**：s01 陷阱「列证据让他认错」、s03 陷阱「用钱/忽略需求」、s04 陷阱「泛泛夸做得好」具备真实诱惑性（文案评审通过）。
4. **P1 不说教**：后果由 NPC 反应说话；复盘用「X 身上发生过」案例，无「你必须」口吻、无额外伦理批注（P2 已移除）。
5. **边缘覆盖**：E1（识别错→`miss`）/ E2（边界强制）/ E3（安全失败）至少被实现且体验正确，不崩溃。
6. **数据驱动**：全部文案来自 `内容数据schema.md` 结构，新增场景不改代码。
7. **轻量反馈**：单局无关系账户 meter；关系信号仅展示不持久化。
8. **竖屏可达**：上述 6 屏在移动端竖屏单屏内可达，单局 ≤3 分钟。
